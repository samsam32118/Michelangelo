# Plan: evidence a human can check, in Claude Code and Codex (2026-10-07)

Status: **proposed**, waiting for the owner. Replaces the earlier `mgl review` plan on this branch (kept in git
history). Nothing is built except `Project.historyEntries()` (additive, 4 lines).

## Why

The human never opens Michelangelo. They watch Claude Code or Codex edit a video and receive an `.mp4` plus the
agent's summary. To trust it today they must rewatch the whole video after every round, or believe the summary.

Trust comes from **inspectability** (I can see what was done) and **diff** (I can see what changed since a state
I accepted). Simple wins: one image and a few lines of text, readable in under a minute.

**Problem statement.** Let a human confirm in under a minute, without watching the video, that the agent changed
what was asked and nothing else, with evidence that appears **whether or not the agent chooses to show it**, and
a one-step undo.

## What Claude Code does, and what we take

| Claude Code | Michelangelo |
|---|---|
| Every file edit is shown as a diff, whether the model wants it or not | evidence is written by `render` every time, not only when the agent asks |
| Every tool call is visible in the transcript | the recorded steps, each with what it changed |
| Checkpoints and rewind make mistakes cheap | `edit undo n` (exists) and `edit approve` (new), a checkpoint to compare against |
| Plan mode / permission modes: a human gate, more autonomy as trust grows | approval is the gate; later diffs show only what changed since |
| `file:line` references | every change names its line in the project file |
| Honest summaries | QA compared before/after: fixed, new, still open |

Video needs one more thing code does not: **pictures**. So the evidence leads with before / after / changed
pixels for exactly the moments that changed.

## Options considered (double diamond, short form)

| Option | Verdict |
|---|---|
| A new `review` verb | no: the agent decides when to run it (the checked controls the check); a 10th verb (R3, R7); duplicates `look` |
| **`look --since`** | **yes**: look already renders frames and runs QA; a baseline turns its sheet into before/after |
| Evidence after every `edit` | no: a render per edit doubles the cost of editing |
| **Evidence written by `render`** | **yes**: the moment a human receives the work; the agent cannot skip it |
| **`edit <file> approve`** | **yes**: approval lives next to `undo`, `redo`, `history` |
| PR comment from a GitHub Action | later: needs GitHub and a PR |
| Claude Code / Codex hooks | later: each host differs; they would call the same engine |
| Separate viewer package; live preview server | no: a second package for nothing; a server needs a browser (R6) and a long-lived process |

## The design: one engine, three surfaces, no new verb

### The engine: `review()` in `src/qa/review.ts` (SDK: `p.review(opts)`)

Input: the current project and a baseline. Output: the change list, the frames compared, the QA comparison,
and three renderings of it:

1. **Summary** (≤ 8 lines, valid Markdown): what the agent relays in chat.
2. **Card** (PNG, long edge ≤ 1568 px so agents can read it too): verdict bar, up to 3 rows of
   before · after · changed pixels, the timeline. One image goes everywhere: a side panel, a PR, a message.
3. **Page** (HTML, self-contained, no scripts, light/dark): everything, for a closer look: all compared frames,
   timeline, field-level changes per entity, the steps with their commands and undo, QA, the raw file diff.

**Baselines** (`--since`):

| Value | Compares against |
|---|---|
| `approved` | the last `edit approve` snapshot (default when one exists) |
| `start` | before every recorded step that still reverses cleanly (default otherwise) |
| `<n>` | before the last n recorded steps |
| `<file.mgl.json>` | any other version, e.g. `git show HEAD:video.mgl.json > old.mgl.json` |

**Attribution.** Each changed entity is tagged with the recorded steps that touched it. Against an approved
snapshot, a change no step explains (a hand edit, an undo, another tool) is grouped in orange as **"not from a
recorded step"**: the part a human most needs to see, and one the history alone cannot reveal.

**Frames are chosen from the changes**, not evenly: the middle of each changed visual clip (both spans when it
moved), each changed cue, plus 3 even frames when a style, track, comp or the project changed. At most 6, deduped.
Sound-only changes show one frame ("no picture change") and list the sound fields. If the comp size changed, the
pixel diff is skipped and says why. Tiles ≤ 640 px tall: about 1–2 s for 6 frames at 1080×1920.

**Pixel diff:** a pixel counts as changed when any channel differs by more than 24; the changed image is the
after frame dimmed, changed pixels in magenta, the changed area boxed, the share of changed pixels printed.

**QA:** the existing no-pixel checks run on both versions; findings are matched by rule, clip and message
into fixed / new / still open.

### Surface 1: `mgl look <file> --since <baseline>` (on demand)

Without `--since`, `look` is unchanged. With it, `look` also writes `.mgl/<p>/look/review.png` (the card) and
`review.html`, and prints the summary before its usual findings:

```
**changes since approved (14:02)** 4 steps · 6 changes · 0 not from a recorded step · QA 1 fixed, 0 new, 2 open
frames: f45 12% changed · f120 4% · f300 no change
| # | step | changed |
|---|---|---|
| 1 | `clip.set title y=380` | title: y 420 → 380 |
| 2 | `motion.apply title in=pop` | title: animate in pop |
card: .mgl/video/look/review.png · page: .mgl/video/look/review.html
approve: `mgl edit video.mgl.json approve` · undo steps 2..4: `mgl edit video.mgl.json undo 3`
```

### Surface 2: `mgl render` (automatic)

Every video or GIF render also writes `<out>.review.png` and `<out>.review.html` next to the output, against
`approved` (or `start` if nothing was approved yet), and adds two lines to its output:

```
changes since approved (14:02): 6 (0 not from a recorded step) · QA 1 fixed, 0 new
evidence: out.review.png · out.review.html
```

The card is made from stills before encoding starts, so `--detach` writes it too. `--no-review` turns it off.
Stills, audio and subtitle outputs skip it. When nothing changed since approval the card says so in one row.

### Surface 3: `mgl edit <file> approve` (the checkpoint)

Saves the current state as `.mgl/<p>/approved.json` (`{at, hash, project}`), next to `history.json`. Prints
`approved: later looks and renders show changes since now`. `edit <file> history` gains a first line:
`6 changes since approved (14:02)` or `never approved`.

## Where humans see it

```
┌───────────────────────────────────────────────────────────────────────┐
│ ● 4 steps since approved · 6 changes · 0 unexplained · QA 1 fixed 0 new │  green / amber
├─────────────┬─────────────┬─────────────┬─────────────────────────────┤
│   before    │    after    │   changed   │ 1.50s f45 · title, shot2    │
│   [frame]   │   [frame]   │ [magenta]   │ 12% of pixels               │
├─────────────┴─────────────┴─────────────┴─────────────────────────────┤
│ … up to 3 rows, the frames that changed most                          │
├───────────────────────────────────────────────────────────────────────┤
│ V1 ▇▇▇▇▇▇[▇▇▇]▇▇▇▇   T1 ░░[▇▇]░░░   A1 ▇▇▇▇▇▇▇▇▇     ▲1  ▲2  ▲3     │  timeline
└───────────────────────────────────────────────────────────────────────┘
```

| Surface | What the human sees | How |
|---|---|---|
| Claude Code, terminal | the summary in the transcript; card and page as paths | the agent relays `render` / `look --since` output |
| Claude Code, desktop / web / mobile app | the card inline in the side panel, the page one tap away | the agent sends `out.review.png` and `.html` as files |
| Claude Code, IDE extension | the project file diff in the editor's diff view | direct edits to the one-entity-per-line file already show as native diffs |
| Codex CLI | the summary in the final message; card and page as paths | one line in `AGENTS.md` |
| Codex cloud / any PR | the `.mgl.json` diff (readable: one entity per line) with the summary and card in the description | the agent pastes the summary; the card where the host can attach images |

What the hosts already give us: native diffs of direct file edits; approval prompts that show plain
`mgl edit video.mgl.json clip.set title y=380` (keep `k=v` readable, avoid opaque JSON in prompts); approval and
undo in conversation ("looks good" → `edit approve`, "undo the last two" → `edit undo 2`). No new buttons.

**The instruction** (one line in SKILL.md, and an `AGENTS.md` snippet in the README for Codex): "When you hand
over a render, give the human its summary and `<out>.review.png`, after looking at the card yourself. Never
claim a change you cannot point to on the card or in the summary. When they approve, run `mgl edit <file>
approve`."

| 7 | Tests: unit tests for diff, attribution and frame choice; a CLI test: 3 edits + 1 hand edit → `look --since start` shows 3 steps; `approve`; 1 more edit + 1 hand edit → `render --draft` evidence shows 1 step and 1 "not from a recorded step" | `tests/unit/` |

Each step lands with its tests passing (`npm run test:fast`), on a branch off `main`.

## Decisions for the owner

- **(Ask)** Evidence at `render` on by default (recommended; it is what makes it independent of the agent), or
  only with a flag?
- **(Ask)** Should `render --final` refuse when nothing was ever approved? Recommended: no; it notes "never
  approved" and goes on. A gate can come later, the way Claude Code grants autonomy as trust grows.
- **(R)** Later: Claude Code / Codex hooks and a PR comment Action, all calling the same engine; reviewing a
  batch of edits before it is applied (`look --since` on a dry run), like plan mode.
- **(R)** Snapshots and evidence stay under `.mgl/` (git-ignored) except the `<out>.review.*` files, which sit
  next to the output the human receives.
