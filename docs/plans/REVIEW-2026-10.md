# Plan: the board, one view a human can trust (2026-10-07)

Status: **proposed**, waiting for the owner. Replaces the earlier versions of this plan (kept in git history).
Nothing is built except `Project.historyEntries()` (additive, 4 lines).

## Why

The human never opens Michelangelo. They watch Claude Code or Codex edit a video and get an `.mp4` plus the
agent's summary. To trust it today they must rewatch the whole video after every round, or believe the summary.

Trust comes from **inspectability** (I can see what was done) and **diff** (I can see what changed since I said
it was good). Simple wins: one picture, two words, nothing new to learn.

**Problem statement.** Let a human confirm in under a minute, without watching the video, that the agent changed
what was asked and nothing else; let them say "this part is done" and be sure it stays done.

## What Claude Code does, and what we take

| Moment | Claude Code | Michelangelo |
|---|---|---|
| Before the work | plan mode: approve the plan first | the board before anything is built is a storyboard |
| During the work | paths and line numbers to point at | scene tiles with ids to point at ("make shot3 shorter") |
| After the work | diffs, shown whether the model wants them or not | the board shows each scene before ⇄ after; `render` always writes it |
| Protecting what is done | permission rules; checkpoints | **approve** = picture lock, verified by pixels; `reopen` is always shown |

## The design: one view, two words, two places

### One view: the board

A row of scene tiles. The same view serves before the work (a storyboard), during it (a contact sheet) and
after it (the review).

```
 1 intro 0–4s ✓🔒   2 shot3 4–8s ● changed   3 shot4 8–12s ● changed   4 cta 12–15s ○ planned
 [frame]             [after ⇄ before]          [after ⇄ before]          [sketch: "CTA, logo"]
 approved 14:02      title y 420→380           +2 captions               not built yet
─────────────────────────────────────────────────────────────────────────────────────────────
 4 scenes · 1 approved · 2 changed · 0 broken · QA 1 fixed, 0 new
```

**Scenes**, in this order:

1. Markers with a length on the main comp (`{"id": "cta", "comp": "main", "at": 360, "len": 90, "note":
   "CTA, logo"}`): a storyboard written before the work. No schema change; markers already have `len` and `note`.
2. Otherwise the shots: each clip on the bottom visual track of the main comp is a scene, named by its clip id.
   Nobody has to write a storyboard first.
3. Otherwise (nothing on that track) 5-second chunks, `0-5s`, `5-10s`, ...

Shot scenes follow their clip: moving `shot3` later in time keeps its identity and its approval.

**Tile states** (one each):

| State | Means | Tile shows |
|---|---|---|
| ○ planned | a marker scene with nothing built in it | a sketch card with the note |
| · draft | built, unchanged since the last approval, not approved | the middle frame |
| ● changed | something in its time range changed since the last approval | after ⇄ before, the changed fields (`title y 420→380`) |
| ✓ approved | locked by the human, still matches | the frame, a padlock, when it was approved |
| ✕ broken | approved, but its pixels or sound no longer match | red; before ⇄ after; which change did it |

A scene that was reopened carries a red `reopened` badge until it is approved again.

**Image:** `board.png`, long edge ≤ 1568 px so agents can read it too, at most 12 tiles (broken, changed and
planned first; the rest counted in the footer). **Page:** `board.html`, the same board, self-contained, about 40
lines of inline script for three things only: a before ⇄ after toggle per tile; hover for what changed, its line
in the project file and the step that did it; click to copy a reference (`shot3 4.0–8.0s`) to paste into chat.
The full step list and the raw file diff sit collapsed under the board.

**Text** (≤ 8 lines, valid Markdown), what the agent relays in chat:

```
**board** 4 scenes · 1 approved · 2 changed · 0 broken · QA 1 fixed, 0 new (since approval 14:02, 3 steps)
- shot3 (4–8s): title y 420→380 · step 2 `clip.set title y=380`
- shot4 (8–12s): +2 captions · step 3 `captions.from-text`
- cta (12–15s): planned, not built
board: out.board.png · out.board.html · approve: `mgl edit video.mgl.json approve shot3 shot4`
```

### Two words: approve and reopen

When someone says "the intro is good" they mean both "compare against this" and "don't touch it". Film calls
this **picture lock**. One word covers both.

- `mgl edit <file> approve [scene ...]` (no ids: every built scene) locks those scenes and makes the current
  project the baseline. It stores the project snapshot and, per approved scene, reference frames (start, middle,
  end, at board size) and the scene's loudness, in `.mgl/<p>/approved/`.
- `mgl edit <file> reopen <scene ...>` unlocks them. Reopened scenes show red on the board until approved again.
- `mgl edit <file> history` gains a first line: `since approval 14:02: 3 steps, 2 scenes changed, 0 broken`.

**Verification by pixels, not by bookkeeping.** Every board re-renders the approved scenes' reference frames
and compares them (a pixel counts as changed when a channel differs by more than 24; a scene is broken when more
than 0.5 % of its pixels changed, its length changed, or its loudness moved by more than 0.5 LU). It does not
matter how the change happened: a command, a hand edit of the file, a plugin, a ripple from an earlier scene.
No lock checks are added to the ~70 commands, and nothing is tracked on the side.

**The baseline is always the last approval.** No `--since` flag, so the agent cannot pick a flattering
comparison. Before the first approval it is the start of the recorded history, and the board says
`never approved`.

**Attribution.** Each change is tagged with the recorded step that made it. A change no step explains (a hand
edit, another tool) is marked `not from a recorded step`.

**QA.** The existing no-pixel checks run on the baseline and the current project; findings are matched into
fixed / new / still open.

### Two places, both existing verbs

- **`mgl look`**: without `--at` / `-n`, the contact sheet is laid out as the board (`sheet.png`, plus
  `board.html`). The agent already runs `look`, so it checks the same picture the human will. With `--at` /
  `-n`, `look` is unchanged. QA crops are unchanged.
- **`mgl render`**: every video or GIF render writes `<out>.board.png` and `<out>.board.html` next to the output
  and prints the text summary. `--no-board` turns it off. Stills, audio and subtitles skip it. The board comes
  from stills made before encoding, so `--detach` writes it too.
- **`render --final` refuses while a scene is broken** (exit 1, fix: `approve` it again or `reopen` it).
  A project that was never approved renders, with a note.

## Where humans see it

| Surface | What the human sees |
|---|---|
| Claude Code, terminal | the text summary in the transcript; `board.png` / `.html` as paths |
| Claude Code, desktop / web / mobile app | the board inline in the side panel (the agent sends it as a file); the page one tap away |
| Claude Code, IDE extension | plus native diffs when the agent edits the one-entity-per-line file directly |
| Codex CLI | the text summary in the final message; the board as paths |
| Codex cloud / any PR | the `.mgl.json` diff, with the summary and board in the description |

**The human gate.** The agent can type `approve` too. Two answers, simplest first:

1. The instruction (one line in SKILL.md, and an `AGENTS.md` snippet in the README for Codex): "Hand over every
   render with its board summary and `board.png`, after looking at the board yourself. Run `approve` or `reopen`
   only when the human says so in this conversation. Never claim a change you cannot point to on the board."
2. The real gate, for people who want it: a host permission rule that makes `mgl edit * approve*` and
   `mgl edit * reopen*` ask before running. In Claude Code that is an `ask` rule in settings; in Codex, the
   approval policy. The human then clicks Allow on every approval. The docs show both.

Every approval and reopen is listed with its time on the page, so an approval the human did not give is visible.

## Not doing, and why

| Not doing | Because |
|---|---|
| A new verb (`review`) | the agent would decide when to run it; `look` and `render` already sit at the right moments |
| Separate card, storyboard, timeline images and a long page | they are one view at different moments: the board |
| Track-by-track timeline picture | tracks are an editor's concept; humans think in scenes; `mgl show` prints tracks as text |
| A storyboard command | scenes default to shots; markers with a length refine them |
| `--since` / `--against` | the baseline is always the last approval; git covers other comparisons |
| Lock checks in every command | approved scenes are verified by pixels and loudness, whatever made the change |
| Drag-to-edit timeline, scrubbing, pinned comments | a second writer next to the agent; needs a live app; point-and-paste does the job |
| Hooks, status line, PR comment Action | later, if wanted; they would call the same board |

**Trade-off accepted:** the pixel check samples three frames per approved scene, so a change confined to a few
frames between them can slip through. If that shows up in use, sample every 0.5 s (cost: a few more stills).

## Build steps

| # | Step | Where |
|---|---|---|
| 1 | Scenes: from markers, shots or 5 s chunks; stable ids; the shot a scene follows (pure, unit-tested) | `src/qa/scenes.ts` |
| 2 | Approval store: snapshot, reference frames, loudness; `approve`, `reopen`, `history` line (`historyEntries()` done) | `src/sdk/project.ts`, `src/cli/edit.ts` |
| 3 | Board engine: baseline, per-scene diff and attribution, states, pixel and loudness check, QA compare | `src/qa/board.ts` |
| 4 | Outputs: `board.png` (Skia, like the contact sheet), `board.html`, the text summary | `src/qa/board.ts` |
| 5 | `look` lays its sheet out as the board; `render` writes it, `--no-board`, `--final` refuses on broken; SDK `p.board()` | `src/qa/look.ts`, `src/cli/`, `src/sdk/index.ts` |
| 6 | Docs: README (two words, one flag), DESIGN §6.1 and §8, SKILL.md line, AGENTS.md snippet, the permission rule | docs |
| 7 | Tests: scene derivation; a scenario: 3 edits → board shows 3 changed scenes; approve 2; 1 edit + 1 hand edit inside an approved scene → broken, `render --final` refuses, `reopen` clears it; a move of an approved shot stays approved | `tests/unit/` |
| 8 | Evals: run the main set before and after step 5 (the agent's `look` sheet changes) and compare | `evals/run.mjs` |

Each step lands with `npm run test:fast` passing, on a branch off `main`.

## Decisions for the owner

- **(Ask)** `look`'s default sheet becomes the board (recommended: the agent and the human then check the same
  picture), or the board is only written next to it?
- **(Ask)** `render --final` refuses while a scene is broken (recommended), or only warns?
- **(R)** Thresholds: 24 per channel, 0.5 % of pixels, 0.5 LU, 3 frames per scene, 12 tiles. Tuned on real
  projects in step 7.
- **(R)** Approval data lives in `.mgl/<p>/approved/` (git-ignored); the `<out>.board.*` files sit next to the
  output the human receives.
